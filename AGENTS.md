# Agent Instructions

Before changing any public interface, copy, component, or visual state, read `DESIGN.md` in full.

`DESIGN.md` is mandatory product policy. Do not treat it as optional style guidance. For every UI change, identify the user task, primary action, information hierarchy, product-specific composition, and mobile/accessibility checks before implementation.

Do not introduce forbidden gradients, glassmorphism, decorative shadows, excess rounded pills, emoji decoration, generic AI copy, or visual effects without a clear functional reason. If an element does not help a user act, understand content, or verify a system state, remove it.


These rules also apply to design handoffs, Figma/artwork, and interactive mockups. Keep DESIGN.md as the shared policy; older examples do not override it.

Read STATE.md and the relevant latest handoff before continuing work. Preserve paused work. See docs/design/UI_UX_AUDIT_2026-10-16.md for the current source-backed gaps and review order. Report checks actually performed; adding a policy or checklist is not evidence that existing interfaces have been fixed.
