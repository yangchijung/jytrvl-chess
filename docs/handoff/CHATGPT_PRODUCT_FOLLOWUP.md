## 狀態色與操作規格

保留既有品牌色。以下配對用於狀態文字及其底色，工程可映射到現有 CSS 變數；需要新增的背景變數另行加入。

| 狀態 | 淺色文字／背景 | 深色文字／背景 | 同時顯示 |
|---|---|---|---|
| 成功 | #166534／#DCFCE7 | #86EFAC／#123225 | 勾選圖示及明確文字 |
| 警告 | #854D0E／#FEF3C7 | #FDE68A／#3D2F12 | 警告圖示、原因及下一步 |
| 錯誤 | #991B1B／#FEE2E2 | #FCA5A5／#3F1D24 | 錯誤圖示及可採取的操作 |
| 資訊 | #1E40AF／#DBEAFE | #93C5FD／#172F4D | 資訊圖示與進行狀態 |

配對的純色文字對比須達 4.5:1；[W3C 對比說明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 為驗收依據。漸層、透明度、停用及 hover／focus 等實際畫面仍需個別檢查。此色票不等於整站通過 WCAG 驗收。主要按鈕的白字若在深色主題現有綠底對比不足，可使用 #246548 底色。

- 主要按鈕、手機方向鍵及圖示操作區以至少 44×44 CSS px 為產品目標；棋盤交點或格子使用適合棋盤的選取方式，不能為達尺寸而造成重疊觸控區。
- 360px 下標題可換行；英文按鈕容許合理換行，不用省略號隱藏主要動作。控制區留出安全邊界及底部 safe area。
- 首頁保留三分類六張遊戲卡；標語置於主標題附近，不把英文版本固定塞入中文版同一行。
- 不以 overflow-x:hidden 作為通過溢出驗收的證據；仍要檢查可見內容、焦點元素及控制區的實際邊界。
- 連線恢復分為「正在重新連線」→「正在同步對局」→「對局已同步」。只有取得有效房間快照並恢復座位／觀戰身分後，才能顯示最後一項。
- 即時遊戲重新連線時的時鐘、移動、淘汰照伺服器規則進行，提示不能保證對局已暫停或保證所有操作保留。

## 雙語文案交付與接線

[product-copy-v1.1.json](product-copy-v1.1.json) 分成 replace 與 add，各有 zh／en 兩份字典。replace 鍵已對照 src/i18n/strings.ts；add 是新鍵，需在對應畫面接線後才生效。占位符在兩語必須完全相同。

內容包含標語、首頁說明、六款遊戲卡、六款開場引導、連線狀態、通用錯誤與暗棋規則摘要。直接將 replace 的值合併至既有 zh／en 物件；add 合併後依下表掛接，不覆蓋整個 strings.ts。

| 新鍵群組 | 顯示位置及條件 |
|---|---|
| onboarding.<game> | 各遊戲首次進入或教學導覽；重新開啟規則時仍可閱讀 |
| online.syncing | 已建立連線但尚未套用房間快照 |
| online.synced | 快照、座位及局面版本均恢復；結束後的房間直接呈現結果 |
| online.reconnectFailed | 重試失敗且畫面提供再次嘗試及離開房間按鈕 |
| rules.xiangqi.version／rules.xiangqi.summary | 象棋規則面板及計分局設定摘要 |
| rules.banqi.summary | 暗棋預設規則面板；自訂規則不可沿用此固定摘要 |
| tutorial.actionDone／tutorial.tryAgain／tutorial.finish | 共用教學回饋；成功必須由既有規則引擎回傳 |

目前棋類教學的逐課文案與成功條件也存在 src/learn/lessons.ts，並非全在 strings.ts。這一包是共用介面及開場文案，既有教學關卡、局面及成功條件保留；後續逐課潤稿要對準實際課程資料，不批次替換成同一套五課。

## 中國象棋判例規格

觸發條件：同一棋子配置與輪走方第三次出現。判定範圍依現行引擎，從該局面第一次出現後到當下的全部循環步驟。先判長將，再判長捉。

| 編號 | 循環內的情況 | 本站預期裁決 |
|---|---|---|
| XQ01 | 紅方每一步將軍，黑方非每一步將軍 | 紅負，perpetual_check；即使黑方部分或全部步驟屬捉子，仍先判長將 |
| XQ02 | 黑方每一步將軍，紅方非每一步將軍 | 黑負，perpetual_check |
| XQ03 | 沒有單方長將；紅方每一步都是將軍或符合定義的捉子，黑方不是 | 紅負，perpetual_chase；涵蓋一將一捉的簡化處理 |
| XQ04 | 沒有單方長將；黑方每一步都是將軍或符合定義的捉子，紅方不是 | 黑負，perpetual_chase |
| XQ05 | 沒有單方長將；雙方每一步都是將軍或符合定義的捉子 | 和局，repetition |
| XQ06 | 雙方都至少有一步既非將軍也非符合定義的捉子 | 和局，repetition |
| XQ07 | 僅靠帥將或兵卒發動的非將軍攻擊，或追逐未過河兵卒 | 該攻擊不算「捉」，依其餘步驟判定，不可直接判長捉負 |
| XQ08 | 剛移動棋子以低價值攻高價值，或目標不能被合法吃回 | 合法吃子威脅算「捉」；牽制導致不能合法吃回時，不算有效保護 |
| XQ09 | 未達第三次，或棋子相同但輪走方不同 | 不因本項條件觸發重複局面裁決 |

此簡化版每步檢查是否有符合定義的捉子，不要求每次追逐同一枚棋子。引擎另有雙方每步皆將軍時判和的防禦分支；若合法對局無法構造，不要求人工編造可重播棋譜。

可沿用 tests/xiangqi.test.ts 的兩組種子作為工程測試起點：

- 長將：起始 FEN `4k4/9/9/9/9/9/9/9/9/R2K5 w - - 0 1`，先走 `a1a10`，再重複 `e10e9 a10a9 e9e10 a9a10`，到規則引擎結束為止，預期紅負。
- 閒著重複：標準起始局面，重複 `b1c3 b10c8 c3b1 c8b10`，到第三次相同局面為止，預期和局。

其餘案例由工程補上合法 FEN、完整走步、預期終局原因、實際結果及測試連結後，才能標成「已驗證判例」。公開規則須提供可追溯棋譜或示意，不能只列上表便宣稱回歸已通過。

## 台灣暗棋確認

維持 [現行規則](../rules/banqi.md)：炮可向上下左右移動一格；吃子必須隔恰好一枚棋子，目標須為已翻開敵子且不受階級限制。兵卒可吃帥將，帥將不可吃兵卒；連吃預設關閉。

無進展以單方一次動作算一步；吃子或翻棋將計數歸零，第 50 步連續無吃子也無翻棋時和局。驗收補齊 49／50 步邊界，以及翻棋、吃子後重置案例；另保留三次重複、無合法動作判負與計分局固定規則的原有測試。
