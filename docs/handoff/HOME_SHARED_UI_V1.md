## 1. 設計方向與理由

**使用者任務：選出想玩的遊戲，直接進入該遊戲。** 首頁是遊戲目錄；主操作是每款的「開始玩」，次操作是「玩法」。

先讓人看到遊戲名稱與真實棋盤／場景預覽，再讀一句玩法。縮短前言，刪除與挑選無關的巨大主視覺、裝飾圈與重複特色區。避免孩子先讀完長段介紹，也不再用一個通往西洋棋的通用按鈕代表所有遊戲。

保留 JY Games、既定標語、紙色背景、墨色文字與森林綠操作色。深色模式採中性深綠灰；以字級、間距、邊線區分層級。每個共用介面使用紙／墨／綠三個色系，紅色只表示警告或錯誤。既有 Logo 及遊戲預覽中的棋子／場地功能色保留，不拿來擴張介面配色。

## 2. 首頁：可直接實作的畫面

由上到下：

1. 共用頁首（第 3 節）。
2. 短前言：H1 使用既定標語「一起玩，一起動腦。」／“Play Together, Think Better.”，保留 data-testid="tagline"；下一行「先選一款，再選玩法。」。不再另顯示重複的大標題、7 Games 英文眉標、通用 Play 或指定西洋棋的 Learn 按鈕。舊 /play 路由仍保留供既有連結使用。
3. 三個分類：棋藝策略 → 即時競技 → 益智挑戰；沿用既有雙語分類名稱。移除分類 emoji，刪去重複的分類說明小字。分類 H2，遊戲名稱 H3。
4. 七張遊戲卡，依現有順序 3／2／2 分組。實際預覽 → 遊戲名稱 → 一句玩法 →「開始玩」與「玩法」。頁面顯示當前語言名稱一次；不再附加 game.*.en 造成英文版重複。
5. 共用頁尾。移除首頁四張 AI／連線／教學／教練特色卡，避免暗示七款都有全部功能。移除與頁尾重複的獨立「關於」連結；其他頁面仍用到的文案鍵不要刪除。

**卡片的連結**

- 「開始玩」使用實心主要按鈕，前往各自現有入口；「玩法」是有底線的次要文字連結，仍有至少 44×44 px 點擊區。
- 七款各有兩個目的地，共 14 個；[文案 JSON](../design/home-shared-ui-v1/copy.json) 內提供完整清單，全部經既有 to() 轉為語言路徑。不要發明不存在的 /learn 首頁。
- 卡片本身不另外包整張可點連結，避免巢狀互動及重複鍵盤停點。輔助名稱帶遊戲名，如「開始玩：數獨」，並包含可見的「開始玩」文字。
- 預覽沿用現有 GamePreview／TerritoryPreview／SnakePreview／BlocksPreview／SudokuPreview，使用靜態遊戲內容；不新增背景動畫。相鄰名稱已提供語意時預覽 aria-hidden，避免重複朗讀。
- 首頁預覽外框改小圓角；需要首頁特有樣式時只加首頁變體，不改實際棋盤規則或遊戲場景。

## 3. 共用頁首、選單與頁尾

**頁首**

- 保留既有 Logo 與 JY Games。背景為不透明 bg，底部一條分隔線；移除 backdrop-blur、半透明背景與浮起陰影。
- ≥1024 px：品牌｜所有遊戲（回語言首頁）｜排行榜；右側語言、主題、帳號／登入、選單。
- <1024 px：品牌｜語言｜主題｜選單。帳號／登入放進展開選單。所有圖示控制皆 44×44 px，間距至少 4 px；容器高度用 min-height 56 px，不以固定高度裁切放大文字。
- **選單按鈕在桌機與手機都保留**；不再橫排九個遊戲連結。320 px 需要時可讓品牌區與控制區分兩列，完整顯示與可點擊優先。
- 語言沿用 switchTo，保留當前等價頁面；主題沿用 dark → light → system → dark 的既有循環與儲存。主題的輔助名稱同時說明目前與下一個模式；系統模式跟隨 OS 且不得寫死成淺色。

**展開選單**

- 使用一般 nav + button + links 的 disclosure，不冒用桌面應用程式的 role="menu"。
- 分三組：遊戲（七款直達）／其他（排行榜、對局紀錄、設定）／帳號（玩家資料與登入或登出，沿用既有權限與行為）。桌機已出現的主要連結可在選單重現，避免裝置切換後缺功能。
- 選單置於頁首下方的文流內，無模糊遮罩。窄螢幕一欄，空間足夠最多兩欄；每列至少 44 px。短螢幕展開後不得把連結困在超高 sticky header：展開時解除整段頁首 sticky，讓文流可正常捲動。
- 按鈕 aria-expanded、aria-controls 對應唯一 id；開啟後焦點留在按鈕，Tab 到連結。Esc 收起並回到觸發按鈕；點外面收起時不把焦點搶回；換頁或換語言後收起並依既有頁面焦點策略處理。
- 當前頁連結有 aria-current="page" 與底線／邊線，不只改字色。避免首頁連結在所有子頁誤判 active。
- 保留跳到主要內容連結；焦點可見並到達 main，不能藏在 sticky header 下。登出及 Google 登入錯誤流程不變。

**頁尾**

- 保留關於、隱私、條款、設定、授權／版權內容；不新增宣傳區。連結可換行且至少 44 px 高，文字不低於 14 px；兩種語言都不水平溢出。

## 4. 共用視覺值與安全接線

完整資料：[tokens.json](../design/home-shared-ui-v1/tokens.json)。這是設計資料，不要把整包 JSON 在執行時下載成另一個主題系統。把值整合至既有 src/index.css。

| 用途 | 淺色 | 深色 |
|---|---|---|
| 頁面底／卡片底 | #FAF7F0／#FFFFFF | #171C19／#202722 |
| 主要文字／次要文字 | #1F2328／#535A50 | #F2F3EB／#BEC6BB |
| 主要按鈕底／字 | #1F4D3A／#FFFFFF | #A9D4B6／#173322 |
| 主要按鈕 hover 底 | #173C2D | #BFDFC8 |
| 焦點 | #1F4D3A | #A9D4B6 |
| 互動邊界 | #767C72 | #8C9D8F |
| 分隔線（非控制邊界） | #D8D9D1 | #465347 |
| 警告／錯誤字與底 | #8E2823／#F8E9E5 | #F3C7BF／#432824 |

接線要點：

- bg、surface、surface-2、surface-3、text、muted、border、focus 沿用既有名稱，更新淺／深／system 的一致定義。header-bg 指向 bg；hero-bg 若仍有引用改純色 bg，hero-text 改 text；card-shadow 為 none。
- 新的控制色對採 --ui- 前綴，例如 --ui-primary-bg、--ui-primary-fg、--ui-primary-hover、--ui-control-border、--ui-danger-bg／fg。Button／LinkButton／Segmented／Toggle 一起接成正確底字對。
- **不要只把舊 --accent-fill 改成淺綠，卻讓白字留著。** 既有 --accent、--accent-fill、--on-accent、--clock-active 及遊戲專用 danger／warn／ok 等配對先保留，避免時鐘、棋盤或暫停原型被錯誤重新配色。新 --ui- 是既有 CSS 的語意變數，不另建系統；等逐款檢查時再遷移舊引用。
- 共用 Notice 使用新的 UI 狀態色對：success／info 用綠與文字標籤；warning／error 用同一紅色系加不同圖示及具體文字。保留舊遊戲狀態色變數，避免批次替換場地提示。
- 卡片分隔線不必符合互動邊界 3:1；輸入框、次要按鈕、未選 radio／switch 等需要辨識的外框，必須使用 controlBorder。不可把 border 與 controlBorder 混用。
- focus-visible 用 3 px 實色 outline、3 px offset；留出外圈空間，不被 overflow 裁切。焦點要涵蓋整個控制區；對透明背景、通知內操作也確認相鄰色。不要用原金色焦點或移除 outline 後沒有替代。
- 字型沿用已載入的字型：主標／分類可用既有 serif，遊戲名稱與操作用 sans。字重、行高明確，不新增外部字型請求。
- 棋盤、棋子、計時器功能色及專屬場景外框／陰影留待逐款整改；本輪不要全域刪除遊戲用 keyframes，或把 SVG／圖片內的功能色當介面裝飾大量替換。

## 5. 共用元件狀態

| 元件 | 本輪行為與視覺 |
|---|---|
| Button／LinkButton | 6 px 圓角；一般目標 ≥44×44，首頁主要操作 ≥48 高。主要實心綠、次要有控制邊線、ghost 有明確文字；danger 用指定成對色。hover／pressed 用指定底色，不用 brightness、位移、彈跳或陰影；pressed 可沿用 hover。 |
| Disabled／busy | 使用明確 disabledText／disabledBg，不對整個元件 opacity 40%。原生 disabled；送出中的動作保留文字，aria-busy，防止重複送出。連結無效時移除 href／to 並呈現非互動文字，不假裝 disabled 但仍可進入。不要為本次外觀改變業務條件。 |
| Card | 8 px 圓角、1 px 分隔線、無 box-shadow。只有需要分組的內容使用 Card；不再卡片包卡片。非互動容器不加 hover 動畫或游標。 |
| Modal | 保留原生 dialog。8 px 圓角、邊線、無 shadow／blur；背景遮罩可用單一黑色 45%，只表達阻擋底層。標題 id 用 useId 等方式避免碰撞。Esc、焦點限制／回復、初始焦點與長內容捲動可用；關閉鍵 44×44。破壞性確認預設焦點放取消。 |
| Segmented | 保留 fieldset／legend 與原生 radio。每組給唯一 name，支援群內方向鍵與 Tab；選取狀態有可見標記／邊線，不只換色。每項 ≥44 高，窄螢幕或長英文改單欄，不把三欄硬塞。 |
| Toggle | 保留 checkbox／switch 語意與設定儲存。44 px 高的整個標籤區可點；軌道／圓形把手是功能形狀可保留，移除把手陰影。focus-within 或等效方式把焦點畫在可見控制區，不畫在 sr-only 小框。 |
| Notice | success／info 保持 status，急迫 warning／error 保持 alert；不要每次 render 重新宣告相同錯誤。以一致 currentColor 線條圖示取代 emoji 字元；帶具體文字及需要的重試動作。訊息不能只靠紅綠區分。 |
| Spinner | 有可讀、在地化的「載入中」預設名稱；避免多重 role=status 重複朗讀。降低動態時改靜態圖示＋文字，不能讓等待狀態消失。不新增假的百分比。 |
| PageTitle／表單 | 既有語意層級保持；標題自動換行，說明不低於 16 px。所有共用連結、欄位、選項都有可見 focus，選取與錯誤不只用色彩。 |

共用互動過渡以 160 ms 的顏色／透明度為主，落在 DESIGN.md 的 120–220 ms 範圍；減少動態時為 0。持續載入圖示若保留旋轉，只表示真實等待且在 reduced-motion 停止；不新增常駐裝飾動畫。停用動態不影響狀態完成、可點時機或回覆內容。
