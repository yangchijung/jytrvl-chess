## ① 機器人快遞站：請 ChatGPT 交付

Claude 已先做規則引擎與可玩試玩頁（使用 Claude 暫畫的簡單 SVG 與暫定關卡，標示為暫定），等 ChatGPT 交付後替換。請交付：

1. **首版範圍（建議更簡單）**：例如先做「順序」6 關（前進、左轉、右轉、拿取、放下），重複／條件留到第二階段；請定案關卡數與解鎖方式。
2. **關卡 JSON**（每關一筆，格式如下）。
3. **原創 SVG**：機器人（朝上下左右四張，或一張可旋轉）、拿著包裹的狀態、3 色包裹、3 色門口、牆／障礙、地板 tile、5 個指令圖塊圖示、成功慶祝、撞牆或走錯的表情；不得烘焙文字。
4. **動畫契約**：每一步移動、轉向、拿取、放下、撞牆、完成的演出與時間；執行中亮起目前指令。
5. **短雙語文案**：主提示、按鈕、錯誤回饋（例：「第 4 步前面有牆」，不說「你又錯了」）、完成語。
6. **驗收清單**（比照 RESTAURANT_SCENE_V2 的 V2-xx 形式）與家庭試玩紀錄方式。

### 關卡 JSON 格式（Claude 引擎已支援）

```json
{
  "id": "R01",
  "w": 5,
  "h": 5,
  "start": { "x": 0, "y": 4, "dir": "N" },
  "walls": [[2, 2], [2, 3]],
  "parcels": [{ "color": "blue", "x": 0, "y": 1 }],
  "doors": [{ "color": "blue", "x": 4, "y": 1 }],
  "blocks": ["forward", "left", "right", "pick", "drop"],
  "maxBlocks": 12,
  "hint": { "zh": "先拿藍色包裹", "en": "Get the blue parcel first" }
}
```

- 座標從左上 (0,0) 起，x 向右、y 向下；`dir` 為 N／E／S／W。
- 過關：所有包裹都放到同色門口。機器人一次只拿一個；走到終點但沒送貨不算過關。
- `maxBlocks` 是可放的指令數上限（不是最短解）；較長但正確的流程也算過關，「更短」只是額外星星。
- 顏色目前支援 `blue`、`red`、`yellow`；需要新增元素（例如單行道、重複圖塊）請在規格中說明，Claude 再擴充引擎。

## ② 逆風探險賽（2026-10-16 工程試玩原型已上線 /trail）

> 2026-10-18 負責人回饋：「不好玩」「孩子玩不太懂」。是否暫停或重新設計待負責人決定；決定前工程不改 /trail。若重新設計，請 ChatGPT 先提出孩子看得懂的核心玩法（一句話目標、每回合一個選擇）再交規格。

機器人快遞站已於 2026-10-16 經負責人試玩「可以」，工程接著做了逆風探險賽的簡化首版（規則：`shared/trail/engine.ts`，地圖：`shared/trail/maps.ts`，皆暫定）。請 ChatGPT 檢視並交付：

1. 規則數值是否合適：每回合 +2 能量、泥巴 2、蘋果 +2（每人每顆一次）、休息最多存 1；集滿森林／山峰／湖泊三章再到營地；先走者每局輪換，同回合到達為平手。最佳走法 4 回合，「快快狐狸」不繞路拿蘋果約 5 回合，「慢慢烏龜」只找最近目標約 5–6 回合。
2. 正式地圖 JSON（每張 10–16 點，相鄰點距離 ≥ 14 以維持手機觸控）：

```json
{ "id": "hills", "name": { "zh": "小山丘", "en": "Little Hills" },
  "nodes": [{ "id": 0, "x": 8, "y": 48, "kind": "start" }, { "id": 2, "x": 22, "y": 20, "kind": "badge", "badge": "forest" }],
  "edges": [[0, 1], [1, 2]] }
```
   `kind`：start／camp／plain／mud／apple／badge；`x` 0–100、`y` 0–64；`id` 依序從 0 起。
3. 原創 SVG：兩位探險者、三種徽章、蘋果、泥巴、營地、起點、能量圖示、地圖底圖（赭色山丘、綠色營地）。
4. 短雙語文案：結果（勝／平手／對手先到，不責備）、回看提示、「下次想換哪個選擇？」選項。
5. 回看設計確認：自動找出「多花最多回合」的一回合，畫出更快路線（綠色虛線），可「從這裡練習」；對手照原局重播，練習結果不改原本輸贏。

## ③ 星球救援隊（2026-10-16 工程試玩原型已上線 /rescue）

逆風探險賽已於 2026-10-16 經負責人試玩「OK」。星球救援隊簡化首版（規則：`shared/rescue/engine.ts`，任務：`shared/rescue/missions.ts`，皆暫定）：

- 三個角色各看一張卡：🧭 導航員＝三條路的狀況（可以走／很遠要 2 段時間／窄路不能載重物／斷橋要 1 片木板修一次／落石不能走）；🔧 工程師＝基地需要的零件；📦 補給員＝倉庫數量、一趟能載幾件、哪些是重物。
- 同一台平板：按自己的角色 → 「把平板交給 X」遮罩 → 本人打開看 → 蓋起來；面對面說話，不做聊天室或連線。
- 共用計畫板：每趟選路＋放零件；三個角色都按「確認」才能出發，改計畫會清除確認。
- 執行：救援車沿路動畫；第一個問題就停，顯示因果鏈（例如「黃色路的橋壞了，車上沒有木板，所以過不去」），不指出是誰的錯；成功時基地亮燈並提示下一關換角色。
- 2 人模式由一人兼兩職；1 人模式三張卡全開，只標為熟悉規則。

請 ChatGPT 交付：
1. 正式任務 JSON（目前 4 個暫定；首版建議 3 段角色教學＋6 個合作任務）：

```json
{ "id": "M2", "name": { "zh": "先修好橋", "en": "Fix the bridge first" }, "time": 2, "capacity": 2,
  "storage": { "panel": 1, "battery": 1, "cable": 1, "plank": 1, "water": 1 },
  "needs": { "panel": 1, "battery": 1, "cable": 1 },
  "routes": { "red": "rocks", "yellow": "bridge", "blue": "long" } }
```
   零件：battery（重物）／panel／cable／plank／water；路：open／long／shortcut／bridge／rocks。任務需讓三張卡都缺一不可（測試會檢查可解）。
2. 原創 SVG：三位角色肖像、救援車、倉庫、基地（暗／亮）、五種零件、五種路況、星球背景。
3. 短雙語文案：角色卡說明、因果鏈句型、交接提示。
4. 確認是否需要「誰負責哪一趟」欄位（企劃寫「誰、做什麼、何時交接」；首版只有路線與載貨）。
5. 連線房間（負責人回饋後新增，/rescue/room/:id）：每人用自己的帳號與裝置加入、只看到自己角色的卡；請一併提供房間相關短文案（邀請、等待隊友、換角色、觀看中）與是否需要「交接卡」的設計。
