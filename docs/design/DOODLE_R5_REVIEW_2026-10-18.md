## D3｜P2：壞檔讀取／備份失敗時可能靜默覆寫原資料（隔離測試重現）
精確取出當前 loadSave 函式，在記憶體 storage 測試；沒有改動使用者瀏覽器資料。
- JSON 無法解析（例如截斷為「{」），或備份 setItem 拋錯時，catch 回傳 blankSave、broken=false，沒有備份或異常提示。
- 使用者接著畫一筆，正常 autosave 成功後原資料被覆寫。定位 src/doodle/pages.tsx:76–86、197。
- 修正：分開處理讀取、JSON parse、schema 驗證及備份寫入失敗；先保留原始內容，無法安全備份時阻止對原 key 的自動覆寫，顯示可下載／匯出原資料或另存新畫的路徑。
- 驗收：無效 JSON、未來 schema、備份空間不足各一例；必須保留原 raw、明確告知、可開始另一張且不覆寫舊檔。原 schema 驗證測試不足以涵蓋這些分支。

## D4｜P2：寫入端可產生讀取端拒收的畫作（隔離純模型重現）
- 原 push 可產生 2001 次操作，validSave 卻只接受 ≤2000；2000 次可讀，2001 次即 false。
- 單筆達 5000 個點也會被 validFreeOp 拒收；實際 pointer move 沒有相對應的點數上限／簡化。定位 shared/doodle/model.ts:72、141、150；src/doodle/pages.tsx:641。

- 修正：寫入、記憶體歷史、讀取邊界一致；採可重播壓縮／筆畫簡化或明示的限制，不能單純截掉早期畫作。連續畫與多次清紙仍須保留結果及合理復原能力。
- 驗收：2000／2001 操作與 4999／5000 點邊界，保存後重新開啟畫面一致；額滿也不能顯示「已存好」但下次讀不到。
