## 1. 遊戲畫面與資訊層次

主畫面是一間溫暖的小餐廳：小熊主廚在料理台後方、客人走進店裡、餐盤端上桌、金幣進錢包、買到的裝飾出現在店內。採柔和卡通與景深分層，先以輕量 2D 動畫達成遊樂器般的角色反應與操作回饋。

主畫面由餐廳場景、錢包、圖像操作列構成，桌機場景約占主要遊戲區的三分之二；手機保留完整主廚、客人和當下操作區，其他景物可裁切。主要任務不依賴表格、閱讀段落或橫向捲動。畫面同時只有一個主提示與一個主要下一步。

- 主提示以 10 個中文字內為目標；按鈕 2–6 字。最多補一行即時回饋。英文依意思翻譯，不硬套字數。
- 長篇教學、完整食譜、採買算式、成本分類及結算明細放入可選「小帳本」，預設收起。
- 餐點圖＋原料圖＋數量同時表達規則，不能只換成 emoji 或把文字縮小。
- 讓孩子先做一個動作，再看到後果。沒有閱讀完或答對反思問題才能繼續的關卡。
- 可按「聽」播放當下短提示；樣稿使用裝置語音合成。正式版需檢查繁中／英文、無語音的替代提示；不自動播音，也不開麥克風。

### 不用輸入年齡的兩層玩法

預設「一起開店」適合 5–7 歲或第一次玩的人：有示範圖卡、採買自動加總、客人圖片預告、無倒數催促。能選菜、看同一箱蛋供應不同餐點、發現做太多會剩下、選盆栽或存錢，即是本階段的有意義選擇，不要求口算完整損益。

8–12 歲可自行展開「小帳本」：先估需求再看合計、查看整包與剩量、比較現金和結餘、重玩改菜單。原有手動調整採買包數保留在帳本的進階控制，不能因簡化首頁而刪掉。這兩層是支援程度，不評孩子聰明或笨；不要求生日。

## 2. 一日主流程

| 階段 | 孩子操作 | 畫面回饋 | 留下的經營概念 |
|---|---|---|---|
| 選餐點 | 點 1–3 張餐點圖卡，用大按鈕選份數 | 入選圖卡打勾，相關原料亮起；同一份米與蛋合併計數 | 賣什麼決定買什麼；原料可共用 |
| 進貨 | 看食材箱，按「買齊 117」或回去換菜 | 進貨車送入食材，錢包減少，米與蛋各只有一個共用箱 | 先扣庫存、整包採買、買多占用現金 |
| 做菜 | 點餐點圖卡／料理台快捷鍵，每次做一份 | 主廚轉身、攪拌、冒蒸氣；原料減少，成品盤增加 | 原料可調配，熟食不能拆回；不要一次做太多 |
| 上菜 | 看客人餐點泡泡，點可送出的餐盤 | 餐盤移到客人、客人回應、售價金幣浮起 | 有適合需求的餐才收到收入 |
| 第二批 | 再看三位客人的圖示，決定用剩料做什麼 | 保留共用庫存，更新成品盤及容量 | 分批備餐保留調整空間 |
| 打烊與裝飾 | 看服務人數與今天結餘，選盆栽或存起來 | 日夜轉場、盆栽出現在店裡、錢包減少 | 收到的錢不全是賺到；裝潢也有機會成本 |

教學模式新增產品決定：**備餐前顯示當批三位客人的首選餐點圖示**。上菜時顯示該客人所有可接受餐點，圖示以「或」連接；吐司替代需求不能藏在文字裡。這是降低閱讀與記憶負荷的線索，不改六位客人、食譜、價格、庫存與成交條件。之後可再設計只給需求範圍的進階挑戰，這輪不新增。

沒有合適餐點時，保留「今天沒有」的溫和告知；客人離開後仍能繼續。零成品／零原料也必須能跳過該批，不能卡死。缺蛋時蛋箱明顯變空，三道受影響餐點同時標示缺蛋；不靠紅色或單一禁用按鈕讓孩子猜。

## 3. 動畫與狀態契約

| 動作 | 建議演出 | 時間目標 |
|---|---|---|
| 選菜 | 餐盤輕抬＋勾選，同種原料匯入同一箱 | 150–250 ms |
| 進貨 | 食材車進場、箱子入庫、錢包更新 | 600–900 ms |
| 做菜 | 轉身／攪拌、蒸氣、成品落盤 | 600–900 ms |
| 上菜 | 餐盤移動、客人點頭、金幣入袋 | 500–800 ms |
| 打烊／裝潢 | 燈光變暖、盆栽落地 | 300–600 ms |

- 使用既有 `shared/restaurant/engine.ts` 作唯一規則來源。每次有效動作先一次性提交並保存結果，動畫只呈現結果；不能在 `animationend` 再扣料／入帳。
- 動畫期間保留當前客人的外觀，播完才呈現下一位；禁止連點造成重複交易。重整或跳過動畫直接呈現已提交狀態。
- 動畫可以加速或略過，尊重 `prefers-reduced-motion`；仍呈現明確的結果和數量變化。暫停不扣時間、不移走客人，不偷偷替孩子作決定。
- 不新增手速分數、客人耐心倒數、強烈閃光、無限慶祝循環。快慢不影響營收或評價。
- 所有主操作支援點選與鍵盤；拖曳上菜只能是可選捷徑。未承諾這輪做硬體遊樂器移植或手把支援。

## 4. 經濟規則維持 V1

沿用 [菜單與庫存規格](RESTAURANT_MENU_INVENTORY_V1.md) 的完整規則及 RT01–RT14。每批最多 4 份、一天最多 8 份、兩批六位客人、固定售價、一次裝飾取捨。供應原料為米、蛋、番茄、青菜、吐司、起司，加餐盒。

三道食譜成本／售價為番茄蛋飯 19／32、蔬菜蛋炒飯 20／35、起司蛋吐司 21／30，成本含包裝。預設兩種飯各三份，採買 117；六份全賣營收 201、成本 117、固定費用 50、結餘 34。起始 500 → 打烊 534 → 盆栽 120 → 剩 414。

共用食材減少重複買整包造成的存貨與現金占用，不是單價打折或立即增加 84 利潤。採買付一次錢；做菜耗用庫存；結算不能再從現金扣一次食材成本。當日熟食及到期青菜報廢，其他可用生料繼續列存貨。盆栽純裝飾，不偷偷提高客流，也不改寫當天營業結餘。

## 5. 素材與樣稿使用

`docs/design/restaurant-v2/assets/` 提供背景、主廚、兩位客人、三餐點、七項原料／包裝、盆栽、金幣與完整場景，共 17 個 SVG。Figma 場景含 150 個可編輯向量；角色與道具分開，方便工程做移動、旋轉、縮放及表情替換。來源與圖層對照在同目錄 `README.md`／`manifest.json`。

`interaction-demo.html` 是繁中互動設計參考，含選菜、合併進貨、做菜、六位客人、結算、盆栽與可選帳本。它有獨立簡化模型，**不要把它複製成第二套正式引擎**。樣稿沒涵蓋正式版的雙語、完整保存衝突處理、手動多買、所有缺料提示和家庭驗收；正式版接回既有引擎與測試。

本輪樣稿已在 390×844 與桌機 1024×900 檢視，並走完預設一日流程核對 201／34／534／414。原創圖像在 Figma 整理與檢視，未引用商業遊戲角色、音樂或截圖，未啟用付費素材服務。需要更多姿勢、嘴型或裝飾時可延伸同一素材風格。

5. 一併確認以下原碼檢視風險（本輪未逐項實機重現）：重開直接覆寫無確認、菜單總份數超過 8 缺早期提示、未送出採買包數是否保存、多分頁重開後序號歸零的衝突、存檔資料完整驗證與損壞備份。以專門案例驗證，不能把原始碼疑點寫成已修好。
