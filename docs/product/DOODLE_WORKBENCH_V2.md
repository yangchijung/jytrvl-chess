## 2. 設計方向與操作

孩子的主要動作是「選顏料 → 混出顏色 → 用這色畫」。主畫面是一張大畫紙與可辨識的顏料盤，一次一條短提示。功能透過位置與圖示表達，說明藏在次層；不把流程改成選課或長問卷。

### 畫板與調色盤

- 平板橫向：畫紙約占可用工作區三分之二；右側顏料、混色盤、結果與用色按鈕。畫紙下方為圖示＋短字的畫筆／填色、橡皮擦、復原、存圖；重做、換新紙仍可在次要工具中找到。
- 手機／直向：畫紙在前、工具緊接、調色盤在後，頁面自然捲動。混色後「用這色畫」將畫紙與短提示帶回視野，焦點到可操作位置；不只把焦點丟到 BODY。Figma 手機稿是可捲動頁面，不能硬塞進固定高度。
- 藍、紅、黃、白、黑五個大顏料點常駐，最近使用五色及「全部 29 色」可直接打開。初次完整色庫也可用，沒有付費、過關或收集鎖。
- 畫畫時點色票＝換畫筆；進入「玩混色」後畫面明示「點兩色，混看看」，點色票＝放到目前色槽。成色與基本色使用相同規則，不再以 BASE_COLORS 限制混色輸入。退出調色時不自動改畫。
- 兩個等量色點＋一個明確「混一混」動作；結果是盤中央較大色塊、色名、兩個來源色。結果色塊可直接選用，另有「用這色畫」。選顏料不用拖曳；拖曳只是可選替代。
- 結果可做下一次混色輸入。「再加白」只在有對應配方時顯示，先把目前結果與白色帶入兩槽，讓孩子看見來源再混，不能一次偷偷連做多個步驟。
- 同色相混維持同色並提示「還是紅色」等，不算新顏色；空槽不混。未支援組合保留兩個來源與畫作，提供「試試這兩色」和可混的配對圖，不回傳黑色、隨機顏色或工程錯誤。第一色選定後用輪廓提示本批可混的第二色，不把直接繪畫色票鎖住。
- 「全部顏色」中，每個成色都能查看兩來源的小配方；點配方可把來源放到盤內。孩子不必猜到配方才能自由畫。
- 「換底圖」開六張實際作品縮圖，點一張就回畫板。每張都有自己的作品，不需先讀題、不以塗滿才算能離開。

### 視覺規則

遵守 DESIGN.md：紙色、墨色、森林綠控制介面，警示依現有語意色。29 色、彩色作品與顏料盤屬功能內容，不作全站裝飾色；不加漸層、漂浮陰影、玻璃、膠囊資料卡或 emoji。

畫板保留白底、明確紙邊；調色盤輪廓與顏料凹槽用向量繪製。繪圖工具有實際筆／填色／橡皮擦／復原圖示和短標籤。填色版顯示填色，切自由畫改成畫筆，不能用同一標籤誤導。

色點可見圓形至少 48 px，主控制 48–56 px；色庫展開後色名可見，近期色點也必須有名稱、可見選取輪廓與鍵盤焦點，不能只用顏色。白色有深輪廓。圖示可小於按鈕，但點擊範圍不可縮小。長色名、英文、400% 工具重排，不強迫水平捲動。

動畫維持 120–220ms；減少動態時立即顯示結果。混色動畫只呈現已算好的結果，不驅動保存與任務判定。深色模式不改畫紙、混色 RGB 值、孩子作品與匯出結果。

## 3. 至少 24 種「可混出的結果」

## 5. 工程與存檔銜接

重用 Canvas 2D＋SVG／DOM、現有工具及存檔保護。Three.js 已允許，若使用只能在不改色碼、不犧牲無 WebGL 可玩與保存的前提下加入；不把換引擎列成這輪前置。

工程需同時處理：

1. `shared/doodle/lessons.json`／`model.ts`：色票、ColorId／Mark、配方索引、反向輸入、成色可再混；不只擴資料而漏型別或驗證器。新的色票可以採色名＋選取記號，不需硬造 29 種圖形。
2. `src/doodle/pages.tsx`：移除「只有 BASE_COLORS 可以入色槽」限制，顯示清楚的繪畫／調色狀態，成色再加白與回畫紙焦點。
3. `shared/doodle/scene.ts`：從單一 fish／固定 Region 改成受模板定義約束的 sceneId＋regionId；同名區域不能跨底圖誤讀。
4. `src/doodle/draw.ts` 與匯出：自由筆畫、格子、六張 SVG 的新色、清除與 PNG 一致；不能只更新畫面色盤而匯出仍限八色。
5. `storage.ts`：先定可驗證的版本遷移，不將 29 色或多底圖資料直接寫回只支援八色／單魚的舊格式。

V2 採新版本命名空間或交易式保存；工程在 PR 說明實際格式與提交邊界。舊 `jy.doodle.v1` 與 `jy.doodle.scene.v1` 原文保留。只有第一次且 V2 不存在時匯入舊自由畫、格子、六任務及小魚；不能每次啟動都用 V1 蓋新作品。保留舊 ID 與色碼、筆畫座標／粗細、undo／redo、完成紀錄。

較新／損壞檔先保護原文；備份、另存、讀回失敗不能覆寫來源。多分頁採真正的交易或單寫入者／鎖，衝突時保留兩邊可恢復作品；不能僅讀兩次就宣稱原子安全。舊快取程式不得把 V2 畫作當成壞 V1 後回蓋。

保持已有每筆與歷史容量保護；增加底圖不能靜默丟掉最舊的一張。額滿時顯示失敗並提供各張匯出，清除／重設需使用者操作。

## 8. 美術來源與限制

本輪由產品端透過 Figma 技能組稿、目視檢查並輸出 PNG；可編輯向量另存 SVG，未用外部角色／商店圖、付費素材或照片。小魚沿用 repo 原創 FISH_ART；其餘五張為本輪原創。Figma 圖為介面示意，控制接線、鍵盤與讀屏語意仍需工程完成，不能靠圖片當互動介面。

正式公開產品不需要呈現「29 色資料模型」「固定配方索引」「SVG 區域」等工程字眼；孩子只看顏料、畫紙、短提示與作品。
